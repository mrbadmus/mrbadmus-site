## Fields the site needed that the contract (plan §API contract) does not name

- Per answer: `unmarked_reason` (or a `marking_state: scored | self_checked | unmarked`). The ledger stores a self-check as `marked_by 'unmarked'`, `unmarked_reason 'self_checked'`; `answerOut` drops the reason, so the page cannot tell "not marked" from "self-checked". The site reads `marking_state` if sent, else `unmarked_reason === 'self_checked'`, else treats it as not marked.
- Per work item summary: `self_checked` count (optional; counted from `answers[]` when absent).
- Per topic: `subject` (for the subject dot), already in the fixture; the plan lists `subject`.
- `/family/home` day states: the contract has `done | missed | due_today | none`; a day with work set for later reads `none` and looks empty. The site also accepts `set` / `ahead`.
- `/family/past-work` items: the site opens an item from its own `answers[]` when present, else from that child's `/activity` by id — either works.
