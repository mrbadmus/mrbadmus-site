# MrBadmus lean lessons

Pupils told Mide the lessons were too wordy to read, and that they sound like AI.
Every lesson teaches exactly what AQA asks for, as simply as possible, in the voice
of a good science teacher at the board. Write like an experienced AQA teacher and
examiner (think Free Science Lessons): what does a pupil need to know and write
to get full marks? Teach that, clearly, and nothing that gets in the way.

## HARD RULE: check the spec before and after every lesson

This is not optional, for any lesson, new or rewritten.

1. **Before writing,** open the correct AQA specification and list every statement
   for this lesson's spec point(s): the content, the key words, the required
   practical if there is one, the maths skills, and any HT-only or Triple-only lines.
   - Specs on Mide's Mac: `~/Desktop/Rainford/Curriculum/AQA/`
     - AQA-8464 = Combined Science: Trilogy (all Combined lessons)
     - AQA-8461 = Biology, AQA-8462 = Chemistry, AQA-8463 = Physics (all Triple lessons)
   - A cloud session without the Mac: download the same spec PDF from aqa.org.uk.
     Never work from memory of the spec.
   - KS3 lessons: use the KS3 pack and the national curriculum KS3 science
     programme of study that the lesson was built from.
2. **Use the right spec for the route:**
   - Combined pages use 8464 only. A Combined page never teaches Triple-only content.
   - Triple pages use 8461/8462/8463, so they include the Triple-only lines.
   - Foundation pages never teach HT-only content. Higher pages include the HT lines,
     marked as Higher.
   - If one lesson serves several routes, hide or show each block by route, and
     check every route separately.
3. **After writing,** go back to the spec line by line and tick each statement
   against the lesson. Anything missing gets added. Anything that isn't in the spec
   for that route gets removed, or moved to Dive deeper if it genuinely helps.
4. **Report it:** each lesson's report has a spec table: statement, where it is
   covered (card or section), and route. Nothing ships with a gap.

## The page, in this order

**1. Start here**
- Just the "If you had to guess…?" question with exactly two options.
- Add one line of set-up only if the question makes no sense without it
  (e.g. "An old filament bulb and an LED light a room equally well.").
  No backstories or dramatic scenes.
- Feedback after answering: one or two short lines that teach the point.

**2. Key words**
- Three or four key words, never more.

**3. Key knowledge**
- All the main learning lives here, as cards pupils tap or swipe to open,
  one idea per card. Keep pupils doing something, not just reading.
- Comparisons go in a tap-to-reveal table (e.g. breathing in vs breathing out:
  ribs, intercostals, diaphragm, volume, pressure, air movement).
- Never shorthand key information ("breathing out is the reverse"). Write it out.
- Misconceptions go inside Key knowledge as a "Easy mistakes" card:
  ✗ the wrong idea, ✓ the right one, one line each.
- Equations: formula triangle (tap to find, chip reads "Written out", never "Learn it"),
  units, and a CFIFA worked example (Step 1 / Step 2 when steps chain).
- Interactive diagrams that work (formula triangles, to-scale Sankey arrows,
  displacement grids) stay. Embedded simulations do not (see below).

**4. Key fact**
- One or two sentences that carry the actual science, the thing an examiner
  wants written. Not a slogan. Bad: "Volume first. Pressure second. Air last."
  Good: "Breathing works by changing pressure. Muscles change the volume of the
  chest, which changes the pressure inside it. Air always moves from high
  pressure to low pressure."

**5. Practice**
- Rungs are labelled "Rung 1", "Rung 2", "Rung 3", "Rung 4" only. No tag lines.
- Ladder 2·2·2·1 and five quiz questions per route stay.
- Feedback after each answer: one or two short lines.

**6. Dive deeper (closed until tapped)**
- Extra detail for pupils who want it: where a model fails, command words,
  extra examples, links to other topics.
- Written to the same plain standard. Dive deeper is not a place for waffle.

## Simulations

- Remove simulations embedded in lesson pages. Many were made in batches and
  don't help pupils see the thing.
- Instead, add one simple link to the matching simulation in the Simulations
  section (e.g. waves lesson → "Try it: Ripple tank →"), which opens it and lets
  the pupil come back to the lesson.
- If no matching simulation exists yet, no link. Mide adds them over time.
- Don't remove a sim Mide has ruled to keep (see the sims shortlist in the repo
  once it exists).

## Length

- No word cap. Use as many words as the science needs, and no more.
  Every line has to earn its place. A lean lesson must never be a half-baked one.
- KS3: sentences of 15 words or fewer. GCSE: no sentence limit, but keep them short.
- One idea per line or card.

## Voice: sound like a teacher, not AI

Write the way Mide would say it to a class. Plain words, short sentences,
British spelling, AQA's exact words for anything that's marked.

Never use:
- "It's important to note", "It's worth noting", "Notice that", "Remember that"
  as filler
- "This is not a technicality", "the whole explanation", "precisely", "crucially",
  "essentially", "fundamentally", "in fact", "simply put", "let's explore", "dive into"
- "not X, it's Y" or "isn't just X, it's Y" contrasts used for effect
- Dashes used for drama; rhetorical questions; dramatic scene-setting
- Words to make it sound clever ("persuade", "settles it", "the atmosphere does
  all the work"). Say what happens.

Do:
- Say the fact, then stop.
- Use the words pupils must write in the exam (e.g. "dissipated to the surroundings
  as heat", "from high pressure to low pressure").
- Read every line aloud. If a teacher wouldn't say it to Year 9, rewrite it.

## Worked example of the standard (GCSE Efficiency)

Start here: "An old filament bulb and an LED light a room equally well. If you had
to guess, which one wastes more energy? A The LED / B The filament bulb."
Feedback: "The filament bulb. It gets hot, and that heat is energy you didn't want."

Key words: efficiency · useful energy · wasted energy · dissipated

Key knowledge cards:
- What efficiency means: how much of the energy you put in is used for the job you want.
- Where wasted energy goes: it isn't destroyed. Most of it is dissipated to the
  surroundings as heat, warming them slightly.
- Sankey diagrams: arrow width shows the energy; energy in = useful out + wasted out.
- The equation: efficiency = useful output energy transfer ÷ total input energy
  transfer (and the power version). No unit. Less than 1. × 100 for a percentage.
- Worked example (CFIFA): 200 J in, 150 J useful → 150 ÷ 200 = 0.75 = 75%.
- Reducing waste: lubrication reduces friction; thermal insulation reduces energy
  lost to the surroundings.
- Easy mistakes: ✗ useful ÷ wasted ✓ always divide by the total in;
  ✗ 120% ✓ nothing gives out more useful energy than goes in.

Key fact: "Efficiency compares the useful energy out with the total energy in.
Wasted energy is dissipated to the surroundings, mostly as heat, so no device is
100% efficient."

## Question IDs: keep them (Mide's rule, 11 Nov 2026)

B2C tracks pupils by question ID, so a silent change breaks a child's history.

- Keep every existing question ID and activity ID wherever the question survives
  the rebuild, even if its wording changes.
- Ship an old-to-new ID map for the unit, `docs/lessons/<wave>/ID-MAP-<unit>.json`:
  every ID kept, changed, added or removed. Activities that are removed are listed
  as "removed". Never delete or rewrite saved child answers in the database.
- Also ship the short map the contract check reads, `docs/b2c/id-maps/<unit>.json`
  (KS3 unit code such as `B4.json`, KS4 `physics-energy.json`): one key per ID that
  moved or went, `null` for retired. `tools/lean_id_map.py` writes both from one source.
- Every new question carries a knowledge-point tag, the same way existing questions
  are tagged.
- Never describe a diagram in words. Draw it.
- List every changed ID in the report.
- Before pushing, `python3 tools/lesson_contract_check.py --unit <unit>` must say SAFE,
  static and with `--drive`.

`docs/b2c/LESSON-DEPENDENCIES.md` is the full rule; read it first. Two traps it names:
a KS4 practice-set ID (`ks4q:`) is a hash of the question's wording, so rewording one
gives it a new ID; and the KS4 lesson only ticks done for a family child while the
"Score N of 4" line under the four-rung ladder is on the page.

## Before you hand in a lesson, check

- Spec table complete for the right spec and route; nothing missing, nothing extra.
- Start here is the question (plus one set-up line only if needed).
- 3–4 key words. Key knowledge is tappable cards or a reveal table.
- No shorthand for key information. Key fact carries the science.
- No embedded sim; a Simulations link if one matches.
- Rungs are plain numbers. Feedback is one or two lines.
- No phrase from the "Never use" list. Read aloud test passed.
- Science checked by an examiner pass; equations balanced; units right.
