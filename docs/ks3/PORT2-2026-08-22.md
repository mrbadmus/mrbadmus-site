## ⚠️ THE FINDING THAT CHANGES THE JOB

**Design's delivery is not what its README says it is, and porting it the way
the README describes would have taken a working page off the students.**

The README opens: *"Amendments to the live class-view file, not a redraw."* The
brief follows it — vendor the file, re-register the parity gate to "Design's
amended structure", swap. Done that way, the live class view would have been
REPLACED by Design's file.

It must not be. The two are different components, and the delivered one is much
smaller. Measured on the two sources rather than inferred:

| | live `Class View.dc.html` | Design's amended file |
|---|---|---|
| conditional branches (`sc-if`) | **45** | 18 |
| loops (`sc-for`) | **14** | 7 |
| view-model keys returned | **102** | ~60 |

The 27 missing conditionals are not decoration. They are, by name:

* **every empty state** — `hasWork`, `noRows`, `noShouts`, `hasBoard`,
  `noBoard`, `showSpine`, `showPinned`, `showFeedback`, `weekPicked`,
  `noWeekPicked`, `fresh`, `canReset`. A class with no work set, no
  leaderboard yet, or no shoutouts has nothing to draw without these.
* **every work-row status** — `r.isMarked`, `r.isMissed`, `r.isOpen`,
  `r.isPending`, `r.retake`, `r.hasBreakdown`, `r.hasNotes`, `r.showScore`,
  `r.showHint`, `r.showWord`, `r.expanded`. Design's file draws one row shape
  with one feedback paragraph.
* **the entire responsive treatment** — `wide` (seven of them) and `narrow`.
  Design's file has no width branch at all; the phone layout lives in those.
* **the leaderboard movement arrows** — `c.up`, `c.down`, `c.flat`, `c.me`.

And seven loops are flattened into literal samples: `lessons` (four hardcoded
`<a>` cards — a topic with three lessons or five would draw four), `docket`
(four literal rows), `benchTasks`, `readings`, `recallStats`, `shoutouts`,
`chasers`.

It would also have undone this week's punch list. Design's file re-introduces,
as sample content, four of the exact defects that run fixed: the lesson cards
are `<a href="#top">` again (P-list unit 5), `now: n === 4` puts the spine's
"now" marker back on Week 04 (P9), `LESSONS IN THIS TOPIC 04` is a literal over
a list of four (P4), and the work list is headed `WORK · SUMMER TERM` (P8) —
which is now in `FIXTURE_TELLS`, so it would have tripped its own gate.

**None of this is Design doing anything wrong.** Every one of those is correct
inside a self-contained sample whose job is to show six themes, a flashcard
deck, a done bench and a recall round. The amendments themselves are exactly
what was asked for and they are good. What is wrong is one sentence of framing
— and the brief inherited it.

**The ruling: the port is a REGION-WISE MERGE, not a replacement.** Design's
own README supplies the list to merge on, and the brief already says the porter
binds to it — *"the changed regions carry data-port-region / data-port-change
markers"*. Nine regions carry a change marker or are new subtrees (bench,
bench-done, bench-reward-slot, term-spine, sidebar-flashcards,
flashcards-overlay, recall-round, account-sheet, leaderboard, plus the topbar's
removed nav item). Four regions carry a region marker and NO change marker —
crumbs, hero, work-list, lessons-panel — and those are left exactly as they
are. That is the whole difference between adopting the amendments and adopting
the sample.

### What the merge needs that the port does not have

The port applies rulings through five mechanisms — `LOGIC` rewrites logic,
`PRUNE` removes nodes, `BINDINGS` swaps text, `SET_ON` attaches handlers,
`REWRITES` splices values into method bodies. **Not one of them can add
markup.** Every mechanism to date has removed or rebound something already
drawn, because until now every ruling did.

The theme picker is six swatch buttons that do not exist on the live page. The
flashcard overlay, the recall round and the done bench are whole new subtrees.
So the merge is blocked on a sixth mechanism — one that GRAFTS a subtree from
Design's amended template onto a node in the live one. That is the keystone:
built once, it carries every remaining phase.

### And the themes need scoped hooks, for a reason worth writing down

Design's tokens are a fresh namespace (`--b-*`, `--pg-*`, `--t-*`). The live
page's are `--st-*`. The bench's ground is `--st-room-panel`, its title
`--st-cream`, its accent `--st-ember`.

`--st-cream` is declared *"cream as used ON dark surfaces"* and is text
colour eleven times — but it is also a **background** once, and that once is
the leaderboard's leader avatar: a cream disc carrying `--st-ink` text, sitting
on the very card that takes the theme.

So a blanket remap of `--st-cream` to `--b-ink` breaks precisely on **Chalk**,
the light theme, where `--b-ink` is #221E1B: the disc turns near-black and
keeps its near-black text, and the week's top student's initials vanish. On the
five dark themes it would have looked perfect, which is the kind of defect that
ships. Verified by reading the declaration and every use, not assumed.

The override therefore has to be SCOPED to the bench, the week spine and the
leaderboard card — and those three sections carry no class or attribute to
scope to: they are bare inline-styled `<section>`s.

So the theme system needs a way to set an attribute on a node by index as well
— a small sibling of `SET_ON`, not a new idea.

## Unit 1 — the donor compiles

Design's amended file now compiles through the same machinery the two live
pages do, as a THIRD page that is never emitted:

    class view              404 nodes ·  58154 tpl ·  27897 logic
    assignment              380 nodes ·  54024 tpl ·  31394 logic
    class view amendments   450 nodes ·  70521 tpl ·   9966 logic   ← donor

Nothing renders it. `build_student_port.py` will read its tree and graft the
changed regions onto the live class view. Compiled rather than hand-copied for
the same reason the brand SVG is captured rather than retyped: it is 70 KB of
Design's markup, and a merge that retyped any of it would drift the first time
somebody tidied a style string.

Two things had to give first.

**Design shipped the source without `support.js`.** The file opens
`<script src="./support.js"></script>` and the delivery folder has no such
file. Every other Design delivery in the repo ships one, and all of them —
`student/`, `c9/`, `c10/` — are the same file, md5 `951ae391…`. Copied that one
in beside the source rather than reporting a blocked compile.

**The standalone does not number like the source, and the compiler assumed it
did.** `capture_imports` finds the brand's rendered SVG in Design's standalone
by matching `data-dc-tpl` exactly. The amended template puts the `x-import` at
13; the delivered standalone renders it at 12, and the compile died there.

Neither is wrong. The standalone is a BUNDLE — it inlines the design system, so
its helmet no longer carries the `<script src="_ds_bundle.js">` node the
source's does, and every index after the helmet shifts down by one.

Index equality was never the property being relied on: this code wants one
thing from the standalone, the rendered innerHTML of an `x-import`, and the
index is only how it finds it. So when every index misses AND the two sides
carry the same number of hosts, they are now matched in document order — and
the fallback PRINTS that it fired, every time. A silent positional match is
exactly what would one day map the wrong SVG into the brand slot on a page with
two imports and never mention it.

**Proved it changed nothing for the students.** `student_template.py --check`
recompiles both live pages and diffs against the committed
`student_templates.json`: PASS, exact match, and the offset warning did not
fire for either. Then a full `build_student_port.py` run — `student/class.html`
and `student/assignment.html` byte-identical before and after.

## Unit 2 — the two mechanisms the merge was blocked on

`SET_ATTR` and `GRAFT`, in `student_rulings.py`, applied by `apply_rulings`.
Both ship INERT — no entries yet — but both are exercised and both refuse.

**`GRAFT`** copies a subtree out of the donor onto a node in the live tree:
`replace`, `append`, `prepend` or `after`. Grafted nodes are RENUMBERED into a
reserved range, `GRAFT_BASE + Design's own index`, because `data-dc-tpl` has to
stay unique — `PRUNE`, `SET_ON`, `SET_ATTR`, the parity gate and the binding
index paths are all keyed on it, and the donor's 0..449 overlap the live page's
0..403 almost exactly. Node 10312 on the built page is Design's node 312, and
subtracting is how you find it in the delivery.

It runs BEFORE the handler pass, so a grafted subtree's own `onClick`
expressions are visible to `SET_ON` and protected by its refusal like any
other.

**`SET_ATTR`** names a node so CSS can reach it. The themes need it because the
bench, the week spine and the leaderboard card are bare inline-styled
`<section>`s, and the override cannot be applied at the root — see the
`--st-cream` note above.

**Both refuse rather than guess**, in the house style: a graft anchored on a
node that is not in the template, a graft copying a donor node that is not in
the delivery, a graft with no stated `why`, an attribute that would overwrite
one Design already wrote, an unknown mode, a graft with no donor tree loaded.
Every one of those was driven and every one raised.

Proved on the real trees: grafting Design's `<style>` node (the six-theme token
block) onto the live root landed it at index 10007, colliding with nothing, and
`SET_ATTR` painted its attribute on node 9. Rebuild after: `class.html` and
`assignment.html` byte-identical, because nothing is grafted yet.

`top_up` now SKIPS the donor when counting which tokens are defined. Its tree
declares Design's `--b-*` and `--pg-*` families and it is not on the page —
only the subtrees grafted out of it are. Counting them would let a token the
live page references and only the delivery defines pass as resolved, and an
undefined custom property does not error: it falls back to the inherited value
and the page looks almost right.

## ⚠️ THE GATE CONSEQUENCE, and why the theme unit is not a small one

`student_parity` drives the generated page against **Design's own file** and
compares resolved colours. The amendments change the DEFAULT bench from
graphite `#1A1512` to harbour `#20363F`. So the first commit that makes harbour
the default turns the parity gate red — correctly, because the generated bench
will genuinely no longer match the file it is compared to.

The fix is NOT to loosen the comparison. It is to declare the divergence, the
way `RULED_DIVERGENCE` already declares the three the behaviour gate carries:
the bench is compared against the AMENDED delivery because Design amended it,
and the work list is still compared against the live file because Design did
not. That is the same "re-registration is deliberate, not loosened" the brief
asks for — it is just larger than a list edit, because parity currently has one
Design reference per page and the merged page needs two.

**That is the next unit, and it must land BEFORE the themes**, or the themes
cannot be pushed at all.

### Two things found on the way that are Mide's, not mine

**1. `profiles` UPDATE is not column-scoped.** The policy is
`Users can update own profile · UPDATE · USING (auth.uid() = id)` with **no
