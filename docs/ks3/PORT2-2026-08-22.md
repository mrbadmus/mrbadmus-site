## Phase 0 — vendoring the delivery

### `Student class view fixes/` → `docs/ks3/design-reference/class-view-amendments/`

Filed as the student reference already is — `README.txt`, `NOTES.txt`,
`standalone/` for the two self-contained files, `source/` for the editable
`.dc.html` plus the design-system bundle.

**The two "states" are ONE file.** `ks3-class-view-bench-open.html` and
`ks3-class-view-bench-done.html` are the same 746,693 bytes and differ in
sixty-eight folded lines, of which sixty-seven are the inlined asset store's
random UUIDs. The single semantic difference is the initial state:

    bench: 'open'        vs        bench: 'done'

Everything else — every region, every theme, the flashcards, the round — is
present in both, exactly as the README says. The port reads ONE surface.

**The port markers are real but are not attributes in the file.** A plain
`grep 'data-port-region="'` finds nothing, which is the sort of thing that gets
reported as a missing marker. The markup lives inside a JavaScript string with
`/` escaped as `/` and the quotes backslashed, so the marker reads
`data-port-region=\"topbar\"` on disk. All 25 are present: 14 `port-region`,
7 `port-change`, 2 `port-action`, 1 `port-ignore`.
