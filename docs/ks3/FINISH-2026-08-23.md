## ⚠️ THE FIRST FALSE PREMISE — the question mirror is NOT carrying 110 wrong answers

This repo's own memory records, of `ks3_ladder_questions` on production:

> the prod mirror is 30 lessons stale AND **110/154 live ladder rungs have the
> wrong answer letter**

The staleness is exactly right. The second half is wrong, and it is the half
that would have stopped Phase 3 dead — a recall bank drawn from a corpus that
mismarks two rungs in three is not shippable to children.

Measured against `export_ks3_questions.py --json`, fingerprinting each row as
`question_ref | answer_letter | md5(text) | (letter:md5(text):correct)*`:

| | |
|---|---|
| mirror rows | 154, across 77 lessons |
| exporter rows | 214, across 107 lessons |
| **lessons missing from the mirror** | **30, every one of them chemistry** (`acids-and-alkalis`, `combustion`, `neutralisation`, `word-equations`, `symbol-equations-and-balancing`, …) |
| rows differing on the full fingerprint | **110** — the number memory records |
| rows differing **order-insensitively** | **2** |

So 108 of the 110 differ **in the ORDER of the options and nothing else**. The
question text is identical, the option texts are identical, and the `correct`
flag is on the same option text in both. Asserted DB-side across all 154 rows,
not inferred from samples:

| assertion | result |
|---|---|
| rows where `answer_letter` is not the letter of the `correct:true` option | **0** |
| rows with other than exactly one `correct:true` option | **0** |

The mirror is internally consistent on every row it holds. **Nobody is
mismarked by it.** What drifted is the exporter's option ORDER, which is
cosmetic: `a-balanced-diet#recall` answers "Carbohydrate, lipid and protein" in
both, at letter A in the mirror and letter B in today's export.

The two genuine differences are `formulae#recall` and `formulae#apply`, and
they are **subscript typography**: the mirror carries `H₂SO₄` and `2CO₂`, and
today's `ks3_data/c2/lesson_05_formulae.py` carries `H2SO4` and `2CO2`. Same
science, same correct answer ("Seven"), same distractor reasoning.

⚑ **For Mide, and it is small.** The source has plain digits where the mirror
has proper subscripts, and the same file uses subscripts correctly in five
other places. So a re-export would make those two questions *worse*
typographically, not better. Flagged, not touched — it is a content-typography
call, not a porting one.

**Consequence for this run:** the ladder mirror is a sound source for the
recall bank, for the 77 lessons it covers. The 30 missing chemistry lessons
mean a class taught only C4–C9 material would draw an empty bank, which is
what `min(6, pool)` and the empty state have to survive.

## PHASE 1a — the espresso page chrome

### ⚠️ THE SECOND FALSE PREMISE — it is not four elements, and one of them does not exist

The brief says *"the four named elements move from near-black to #4A3728, per
the anchor map."* Measured in a browser, sweeping every rendered element for
near-black paint and classifying it as page chrome (outside
`[data-bench-surface]` and `[data-bench-docket]`) rather than bench:

| live node | what | before | Design's donor |
|---|---|---|---|
| 118 | term-spine legend **DONE** dot | `#221E1B` | donor 142 `var(--pg-strong)` |
| 166 | work-row **MARKED** dot, ×3 rows | `#221E1B` | donor 171 `var(--pg-strong)` |
| 132 | week-tile **DONE** trough segments, ×4 | `#221E1B` | no counterpart |

**The top rule is ABSENT from the live page.** It is not near-black; it is not
any colour. Design's amended delivery draws a 5px `var(--pg-strong)` bar above
the topbar at donor node 10, and Design's ORIGINAL delivery — which the port is
built from — contains zero occurrences of `--pg-strong` and no such node.
Measured: there is no element of any colour in the top 40px under 10px tall.

So it cannot MOVE to espresso; it would have to be ADDED. And donor node 10
carries neither `data-port-region` nor `data-port-change` — which this run's
own predecessor established is *"the only trustworthy signal about what Design
amended"*. Adding a visible bar to every student's class page on the strength
of a README noun is a design decision, not a colour port. **Mapped, deliberately
not taken; it is one `GRAFT` line whenever it is ruled.**

**And a fourth element moved that Design does not name.** The legend DONE dot
Design *does* name is a KEY, and what it keys is the week-tile DONE segments.
Moving the key to espresso and leaving its referent near-black would leave the
legend telling a student that a colour means something, in a colour no longer
on the page. Faithfulness to Design's list read literally would have shipped a
page that contradicts itself.

So: **three anchors, eight rendered marks** — against two that Design names and
the live page actually has.

### The mechanisms, and why each

| what | mechanism | why |
|---|---|---|
| nodes 118, 166 | `SET_ATTR` → `data-page-strong` + a scoped rule | the colour is a LITERAL `var(--st-ink)` inside Design's inline `style` attribute, so there is no string in the logic to anchor a `LOGIC` rewrite on. This is the shape `[data-bench-avatar]` already uses |
| node 132's segments | `LOGIC` | it is a COMPUTED colour string, like `ring` directly above it |

The `LOGIC` anchor is the WHOLE line, not the token: bare `var(--st-ink)`
occurs **seven** times in Design's logic and anchoring on it would have matched
the wrong one. Verified by counting before it was written. Only the DONE branch
moves — `'open'` stays `--st-accent`, `'missed'` stays `--err`.

`_PAGE_STRONG` in `build_student_port.py` is one rule:

```css
[data-page-strong]{background-color:var(--pg-strong)!important}
```

`--pg-strong` is declared **exactly once** on the built page — in the `:root`
block grafted from Design's node 7 — so this references Design's value rather
than copying it. `!important` is load-bearing for the reason node 266 already
documents: an inline declaration outranks any selector, and without the keyword
the rule parses, matches, loses, and the page looks exactly as if it were
absent. `background-color` rather than the shorthand, so the flag covers only
the component being replaced.

### ⚠️ Espresso is a PAGE colour, not a THEME colour — and that is the safety margin

`--pg-strong` is a fixed hex on `:root` that no `[data-bench-theme]` rule
touches. Measured on all six themes and on the attribute's absence: every mark
reads `rgb(74,55,40)` on all seven, and the page ground stays
`rgb(251,243,230)`.

| mark | before | after | on cream |
|---|---|---|---|
| legend DONE dot ×1 | `#221E1B` 15.02:1 | `#4A3728` | **10.20:1** |
| work-row DONE dot ×3 | `#221E1B` 15.02:1 | `#4A3728` | **10.20:1** |
| week-tile DONE seg ×4 | `#221E1B` 15.02:1 | `#4A3728` | **10.20:1** |

That fixedness is exactly the margin the term spine's `numColor` note records:
page chrome routed through a THEME token would put `--b-ground` on the cream
page at about 1.1:1 on Chalk. The defect is not repeated, and it is asserted
rather than observed.
