## 5 · WS-3, the leaderboard system — shipped, pushed (7aa485d87 · 49fe0d122 · the R30 loading-state commit + backend 6e5bf1a), verified live

**The plan, written before building (docs/MRB-290-plan.md):** Design's page
runs on a ten-field per-student record; everything below her `deco()` is
presentation. So the system is ONE new backend endpoint,
`/api/weekly-leaderboard/board`, and a data seam that feeds her arithmetic
real rows in her own shapes.

**Derived vs captured — the audit came out clean: EVERYTHING derives.**
Production already records per-paper time, subject, tier and pathway on
every attempt, across 11 recorded weeks with zero nulls. Movement (vs the
previous ATTEMPTED week — a week nothing happened is not a competition
week), streaks (consecutive entered weeks), median, fastest single paper,
biggest climb, cut line, entries, per-week strip tops, and the viewer's own
rank are all computed at request time from `weekly_scores`. **No new
tables. No DDL. No stored copies that can drift.** Weeks recorded before
tonight need no honest "—" because every column the derivations touch has
existed since launch; the "—"s that do render are data states (paper not
sat, no positive climb, week one having no movement).

**The board rule, kept and made structural:** only the top 10 rows plus the
signed-in viewer's own ever LEAVE the server. Ranks beyond 10 are computed
server-side precisely so the names behind them never ship. Header stats are
server-computed over the full board for the same reason.

**Countdown:** the close instant is computed server-side by the same manual
BST/GMT rule the challenge reset already uses, and the page ticks against
server time with the device-clock skew captured once. Never the device
clock, never a literal.

**Identity frozen, and the tells gate is unusual for a reason:** real
usernames are generator-style — `WolfSummit53` is a real student while
`FoxWave21` is Design's invention — so a "looks like sample data" sweep is
useless here. The gate derives the exact 61 sample handles from the
delivery's own constants on every run and pins those strings. Zero hits
across all 1,363 served files. Who appears, and under what name and
avatar, is exactly the live rule (`username || first_name`, avatar_url) —
avatars render inside Design's disc with her monogram as fallback, and the
URL is REJECTED (not escaped) if it carries anything that could break out
of the CSS it lands in.

**Your two rulings, in place:** the cream design language is untouched below
the nav, and the nav is the LANDING PAGE's — full-bleed, wordmark hard
left, cluster hard right, gold-to-rust chevron — replacing Design's inset
nav wholesale (which also removed the student-surface BrandMark a root page
must not carry).

**What the port corrected in the delivery, recorded as rulings (29 total):**
