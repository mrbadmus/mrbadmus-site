/* ── ⊕ MRB-242 · TWO ELEMENTS THAT SHIPPED `hidden` AND WERE NOT ───────── */
/*
   Both were found by MRB-242's gate, which asks the CASCADE rather than the
   painted page: an element carrying `hidden` whose stylesheet gives it a
   `display` is OPEN before JS runs, and with JS off it never closes. A
   screenshot cannot see this and neither can computed style.

   ⚠️ `.ks3-mbench-setrow` IS P1's OWN, and it is P1's own shared row rule
   that broke it: `display: flex` at (0,2,0) beats the UA's `[hidden]` rule at
   (0,1,0), so the two settings rows the student has not chosen were laid out
   under the one they had. Scoped back here rather than by dropping the row
   from the flex group, because the group is what makes all eleven control
   rows wrap identically.

   ⚑ `.ks3-bar-cover` IS NOT P1's. It is C2's part-whole bar (`r_cover_bar`,
   `build_ks3.py`), and the defect has been live since MRB-220 landed it: the
   three cover plates are emitted `hidden`, and `<g>` computes `display:
   inline` from the UA stylesheet, so `wireCoverBar`'s inline `display:none`
   is the ONLY thing closing them. Before JS runs, all three plates are drawn
   over the bar at once and the model is unreadable.

   ⚑ IT WAS NEVER SEEN BECAUSE NOTHING WAS LOOKING. `c2-06` is the only other
   page in the key stage that renders a cover bar and it has no row in
   `ks3_parity.COMPONENTS` — and MRB-242's sweep runs over `_registered_
   pages()`, which is exactly the pages COMPONENTS and CONTRAST name. P1 is
   the first unit to register a parity row on a page that draws this
   component, and registering it is what turned the light on.

   Corrected rather than reproduced, on the build contract's R4: a defect on
   an approved page that a ruling already covers is corrected. The rule is one
   line, it is scoped to the component, and it fixes `c2-06` in the same
   breath. Reported.
*/
.ks3-mbench .ks3-mbench-setrow[hidden] { display: none; }
.ks3-bar .ks3-bar-cover[hidden] { display: none; }
