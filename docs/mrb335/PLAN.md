## 1. Scope model

- Cohort of a class = `(key_stage, science_pathway, science_subject)`.
  KS3: `('KS3', null, null)`. Combined: `('KS4','combined',null)`.
  Triple: `('KS4','triple','biology'|'chemistry'|'physics')`.
- Name rule (KS4 only, applied by a DB trigger on INSERT when the columns are
  NULL, and by the admin route on demand):
  `/Sc` → combined, subject null; `/Bi` `/Ch` `/Ph` → triple + that subject;
  tier = foundation when the name ends `Sc4 Sc5 Bi4 Bi5 Ch4 Ch5 Ph4 Ph5`,
  higher otherwise; any other shape → all NULL. Case-insensitive on the band
  letter (`10A/Bi1` is real). `tier_pathway_source` = `rule` when the trigger
  filled it, `admin` when a person set it.
- Tree per cohort:
  - KS4: `generate_site_v5.PATHWAY_TOPIC_MAP[(pathway,'higher')]` gives the
    topic ids; subtopics from `ks4_data.classify()` (mirrored into the backend
    as a JSON constant `ks4-tree.json`, generated by
    `export_ks4_tree.py`, committed in BOTH repos — the backend cannot import
    Python). Combined omits `triple_only` subtopics and omits a topic whose
    subtopics are all triple-only (`space`). Triple shows the one subject only.
  - KS3: `ks3_data` units → lessons (`ks3-tree.json`, same exporter).
- Paper tags (KS4 only, combined only shown): see RISKS C8.
- Pool per (scope, tier, pathway) — MCQ only, never filled from elsewhere:
  - KS4 Foundation: `tier='foundation'` rows, all bands; `triple_only=false`
    when combined.
  - KS4 Higher: `tier='higher'` rows (any band) ∪ `tier='foundation'` rows in
    `standard|harder`; same pathway rule.
  - KS3 Easy/Medium/Hard = band easier/standard/harder within the unit or
    lesson.
  - Set work reads ALL `bank_position`s. AUTO composition reads only
    `bank_position < 12` in both mirrors (RISKS D7).

## 3. Endpoints (all under the existing auth; unauthenticated → 401)

`GET /api/teacher/set-work/scope?class_id=`
→ `{ class:{id,name,key_stage,pathway,subject,default_tier,open_from},
     tiers:[…], cohort_classes:[{id,name,pupils}],   // same cohort, caller may set
     subjects:[…], papers:[1,2]|null,
     tree:[{ id, name, subject, paper, counts:{<tier>:n}, last_set_at,
             children:[{ id, name, counts:{<tier>:n} }] }] }`
   Counts are computed for every tier in one pass. `last_set_at` per topic
   for THIS class this academic year (`source='teacher'`).

`GET /api/teacher/set-work/preview?class_id=&tier=&scope_kind=&scope_ref=&count=&exclude=a,b`
→ `{ picked:[{id, subtopic|lesson, subtopic_name, stem, options:[4], correct_index, band}], available:n }`
   Round-robin across subtopics, shuffled within; prefer ids not set to this
   class this academic year; fall back to the full pool when short.

`GET /api/teacher/set-work/swap?class_id=&tier=&scope_kind=&scope_ref=&exclude=`
→ one row in the same shape, or `204` when none remain.

`POST /api/teacher/set-work`
   `{ class_ids:[…], tier, scope_kind, scope_ref, question_ids:[…], title, release_at|null, due_at }`
→ `{ success:true, assignment_ids:[…], release_at, clamped:bool }`
   Validation (400 unless stated): caller teaches / covers / administers every
   class (403); all class_ids share a cohort; tier valid for the key stage;
   scope in the class tree; every id in the pool for scope+tier+pathway with
   four options; 1 ≤ n ≤ 20; no duplicate ids; `due_at > release_at`;
   `release_at ≥ now − 5 min` when given; `due_at ≤ now + 365 d`; title 1–80.
   Atomic across classes (v1's pre-flight + rollback stays).

`POST /api/admin/class-tier` `{ class_id, tier, pathway, subject }` — school
admin only; KS4 only; validates the triple; writes; audit
`class.tier_pathway.set` with `{from, to, acting_as_admin:true}`.

v1's `/topics` route and its `sow_entry_id` contract are deleted.
